# Password Reset

`POST /auth/password/forgot` **always returns `202 Accepted`**, whether or not the email
corresponds to a real account. This is deliberate: a `404` for unknown emails would turn the
endpoint into an account-enumeration oracle — an easy way to test which email addresses have
accounts, one request at a time.

## The token

The reset token is generated by Identity's default token providers — a stateless,
data-protection-encrypted token rather than a stored one. It carries the user id and a snapshot of
the account's security stamp, so a token stops working once the password (or any other
stamp-changing property) changes, and **expires one hour after issue**. That lifespan is set
explicitly, overriding Identity's one-day default, and the same value drives the "expires in"
sentence the reset email shows — so the configured expiry and the copy a recipient reads can't
drift apart. The token is stateless rather than stored, so it isn't strictly single-use: it stops
working once a reset _succeeds_ or once it expires, but until then the same link can be followed
again.

## Delivery happens off the request path

The handler composes the email, then hands it to a queue and returns immediately — a background
worker drains the queue and performs the actual SMTP conversation. This is what keeps the
endpoint's _latency_ identical for known and unknown accounts. Before this design, the known-account
path additionally awaited a multi-round-trip SMTP conversation that the unknown path skipped, so
the two were distinguishable from outside despite both returning `202 Accepted`.

Consequences worth knowing:

- **The queue is in-process and not durable.** A crash, or overflow of the message queue, loses
  queued email — the drop is logged (without the recipient address) and the user has to request
  another reset. A deliberate trade: an unbounded queue behind an anonymous endpoint is a
  memory-exhaustion vector, and a dropped reset is recoverable where an out-of-memory process is
  not.
- **Delivery failures never reach the caller.** `202 Accepted` means the request was accepted, not
  that mail was sent.
- **Shutdown drains the queue** within a short window, so a redeploy doesn't silently swallow an
  in-flight reset email.

See [Observability & Local Dev Workflow → Dev mail sink](../features/observability-and-dev-workflow.md#dev-mail-sink-mailpit)
for how to actually watch this happen locally via Mailpit.

## A residual timing signal, and why it's acceptable

Queueing the reset email removed the _large_ timing signal — the SMTP conversation. What remains is
that a known account additionally runs a password-reset-token-generation operation (an
encrypt-and-sign step over already-loaded user state, on the order of tens of microseconds) after
the account lookup both paths share. That's one to three orders of magnitude below normal network
and pipeline jitter — exploiting it needs a large sample from a low-noise vantage point rather than
a single observation. It's a narrow residue, not a closed hole; see
[Known gaps](./known-gaps.md) for what would close it.

## The email itself

The reset email is a branded HTML message — one accent colour, one call-to-action button, no
countdown timers, no urgency language, and no imagery beyond the Cinedex logo. That restraint is
deliberate: a password-reset email is a security email, and ornate branding plus urgency framing is
also the signature of phishing. The design considered a more distinctive "ticket stub" treatment and
a bare-minimum "Stripe/GitHub style" layout before settling on this middle ground — branded enough
to look like a real product, restrained enough not to look like an attack.

The message ships as `multipart/alternative` with a plain-text fallback alongside the HTML, and the
logo is embedded as an inline image rather than linked, so it renders without a second network
request. No user-supplied data is interpolated into the template — deliberately including no
personalized greeting, since the reader is always the recipient — so the body is injection-free by
construction rather than by careful escaping.
