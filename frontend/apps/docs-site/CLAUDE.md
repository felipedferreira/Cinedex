# @cinedex/docs-site

A Cinedex-branded [Docusaurus](https://docusaurus.io/) 3 site (classic template, TypeScript), scaffolded with `npx create-docusaurus@latest docs-site classic --typescript`.

One of three apps in the `frontend/` npm workspace — see [`../../CLAUDE.md`](../../CLAUDE.md).

## Commands (from `frontend/`, the workspace root)

```bash
npm run docs-site                       # http://localhost:9004
npm run build -w @cinedex/docs-site      # static build to build/
```

Both delegate to this package with `-w @cinedex/docs-site`.

## Layout

```
docusaurus.config.ts     # branding, navbar/footer, blog disabled (blog: false), the Tailwind PostCSS plugin
Dockerfile / nginx.conf  # production build and static Compose runtime
scripts/sync-changelog.mjs  # generates src/pages/changelog.md, see Notes
src/css/custom.css       # Infima wired to @cinedex/theme's tokens, see Notes
src/css/tailwind.css     # Tailwind utilities WITHOUT preflight, see Notes
src/global.d.ts          # /// <reference> for Docusaurus's ambient module types
docs/features/           # product/architecture docs, adapted from README.md + backend/frontend READMEs
docs/security/           # auth/authz docs, adapted from docs/auth-security-model.md + the auth design specs
static/img/               # favicon.svg (copied from cinedex-app) — the only static asset here
```

## Notes

- **`/changelog` is generated, not written.** `scripts/sync-changelog.mjs` copies the root `CHANGELOG.md` into `src/pages/changelog.md` (git-ignored, see `frontend/.gitignore`) before every `start`/`build`, chained with `&&` — the same pattern `cinedex-app`'s `"build": "tsc -b && vite build"` already uses, not npm `pre`/`post` hooks. It also rewrites repo-relative markdown links (`docs/auth-security-model.md`, etc.) to absolute `github.com/felipedferreira/Cinedex/blob/main/...` URLs, since this site only hosts a handful of pages, not the whole repo — `onBrokenLinks: 'throw'` in `docusaurus.config.ts` would otherwise fail the build on every such link. **Edit only the root `CHANGELOG.md`** — never `src/pages/changelog.md` directly, it will be overwritten.
- **`start` runs the dev server and a changelog file-watcher concurrently** (via the `concurrently` devDependency): one shot of the sync script first (so `src/pages/changelog.md` exists before Docusaurus's initial content scan), then `docusaurus start --port 9004` alongside `sync-changelog.mjs --watch`, which re-syncs on every change to the root `CHANGELOG.md` so the page hot-reloads.
- **This package keeps Docusaurus's own generated `tsconfig.json`** (`extends: "@docusaurus/tsconfig"`) rather than the `tsconfig.json` + `tsconfig.*.json` split `cinedex-app`, `@cinedex/storybook` and the `@cinedex/*` libraries use. That split exists because Vite's build reads tsconfig for module resolution and needs a separate node-context config for `vite.config.ts`; Docusaurus's own bundler doesn't read tsconfig for compilation at all — the file exists only for editor support and the `typecheck` script (`tsc`, no-emit). `projectService: true` in the root ESLint config still resolves this single file as the nearest tsconfig, same as every other package.
- **This site consumes the design system directly** — `@cinedex/theme`, `@cinedex/atoms` and `@cinedex/solution` are real dependencies, same as the SPA's. `src/css/custom.css` points Infima's `--ifm-*` variables at the tokens (accent, surface, ink, borders, fonts, code background) instead of restyling Docusaurus, so a rebrand still touches only `tokens.css`. This replaced a hand-transcribed HSL copy of `--accent` that had already gone stale; the six shades Infima needs beyond the base are `color-mix`ed from the token, which needs no wider browser support than the `light-dark()` the tokens already require.
- **`src/css/tailwind.css` deliberately does NOT import Tailwind's preflight**, and that is the whole reason it exists rather than importing `@cinedex/theme/tailwind.css`. Preflight is a global element reset; Infima styles those same bare elements, so the design system's own entry point would restyle every documentation page as the price of styling three components on the homepage. It composes the parts instead — `tokens.css`, `tailwindcss/theme.css`, `tailwindcss/utilities.css` and `@cinedex/theme/theme.css` (the shared `@theme inline` bridge, which lives in its own file in that package precisely so this import can exist). **Utilities are imported unlayered**, unlike `@import 'tailwindcss'`: Infima is unlayered CSS and unlayered CSS outranks every cascade layer, so layered utilities would lose to Infima's plain `p`/`ul`/`a` rules on our own components. Ties against Infima's own classes are settled by source order, which is why `tailwind.css` is **last** in `customCss`. Its `@source` lines cover this site's `src/` as well as the three library packages, and they fail silently — a missing one means correct markup with no CSS at all.
- **Tailwind runs as a PostCSS pass via an inline plugin in `docusaurus.config.ts`** (`configurePostCss`), because Docusaurus is webpack where the SPA and Storybook use `@tailwindcss/vite`. **`docusaurus start` does not hot-reload that** — a change to the `plugins` array needs a dev-server restart, and until then the served stylesheet still contains a literal `@tailwind utilities;` and every library component renders unstyled. Check for that string before debugging anything else.
- **The homepage remounts on colour-mode change (`key={colorMode}` in `src/pages/index.tsx`) and the key is load-bearing.** Chrome does not re-resolve a `light-dark()` value on an existing element when `color-scheme` changes if that property is being transitioned — `Button` carries `transition-colors`, so without the remount both CTAs keep the previous theme's fill and border after a toggle (a near-white button on a white page) while `Card`, which has no transition, repaints fine. The cost is that the brand's 1.2s intro replays on every toggle. `custom.css`'s `:root[data-theme='light'|'dark'] { color-scheme }` rules are the other half: Docusaurus's toggle sets `data-theme` and knows nothing about `color-scheme`, which is what the tokens actually resolve through. They are written `:root[…]` (0,2,0) so they beat `tokens.css`'s own `:root` rule on specificity rather than on import order.
- **`BrandApertureAnimation` cannot server-render, and this is the only app that prerenders.** `useDelayedReveal` reads `window.matchMedia` in a `useState` initializer, which runs during render; `@cinedex/solution`'s comment there still assumes no consumer server-renders. The homepage wraps it in `<BrowserOnly fallback={<Brand />}>` — the static mark is SSR-clean, so the prerendered HTML carries the logo and nothing reflows on hydration. Anything else pulled from these packages needs the same check: browser globals inside `useEffect` are fine, browser globals during render are not.
- **`docs/` holds two hand-authored categories, not an autogenerated dump of the repo's markdown.** `docs/features/` and `docs/security/` are curated, one-time adaptations of the repo's own docs (root `README.md`, `backend/README.md`, the frontend package READMEs, `docs/auth-security-model.md`, and the two auth design specs under `docs/superpowers/specs/`) — not a live sync like `/changelog`. That's deliberate: those source docs vary too much in voice and intended audience (some are publication-quality prose, others are dense internal/library-engineer material) for a mechanical copy to work. **This means the site can drift from the source docs over time** — there's no automated re-sync, so a change to `docs/auth-security-model.md` or a backend README doesn't propagate here automatically. `_category_.json` in each folder sets the sidebar label/position; `sidebars.ts`'s single `docsSidebar` autogenerates the rest from folder structure and each page's `sidebar_position` front matter.
- **`docs/security/how-this-was-built.md` is missing a live issue list on purpose.** It's adapted from `docs/superpowers/plans/2026-07-29-auth-execution-plan.md` (a Linear-project-coupled execution plan) and the two design specs, but ships without a live Linear issue list — the Linear MCP connector wasn't authorized when this content was written. Extend it once that connector is available, rather than hand-copying issue data that can't be kept current.
- **Every diagram is a ```mermaid fence — there is no ASCII box art in `docs/`, deliberately.** This needs _two_ things wired in `docusaurus.config.ts`: `markdown: { mermaid: true }` and `'@docusaurus/theme-mermaid'` in `themes`. **Docusaurus does not error on a fence language it doesn't recognise** — it renders it as a plain code block. So removing either one turns every diagram back into raw `flowchart TD ...` text _with a green build and a passing CI_; this exact failure shipped once already. `themeConfig.mermaid` maps the light/dark Mermaid themes, which is load-bearing because `colorMode.respectPrefersColorScheme` is on. `scripts/check-diagrams.mjs` runs as part of `build` and fails it if either half of that wiring goes missing. It checks **only** the wiring — the content rules (no ASCII box art, no `;` inside a `sequenceDiagram`) are repo-wide and owned by `scripts/check-diagrams.mjs` **at the repository root**, which CI runs as its own step; they are not duplicated here, so a violation is reported once. Both are **static** checks: Mermaid renders client-side, so neither can catch every syntax error. Verifying a diagram change means **looking at the rendered page**.
- **Search is a local, build-time index** (`@easyops-cn/docusaurus-search-local`), not Algolia — no account, no application, no network call from the rendered page. `hashed: true` cache-busts the index filename per build. It only produces an index during `docusaurus build`; **`docusaurus start` has no search box**, which is expected, not a regression.
- **`@docusaurus/faster`'s dependency tree needed two `allowScripts` entries** in the root `frontend/package.json` (`core-js: false`, `@swc/core: false`) to get past `.npmrc`'s `strict-allow-scripts` — see `../../CLAUDE.md` for why both are safe to skip. Neither `@docusaurus/theme-mermaid`/`mermaid` nor the search plugin added any new install script, so no further entries were needed.
- **Compose serves a production build at `https://localhost:9000/documentation/` through Caddy**, with direct diagnostics at `http://localhost:9004/documentation/`. The Docker build sets `DOCUSAURUS_BASE_URL=/documentation/`, while a bare `npm run docs-site` leaves it unset and serves from `/`. The multi-stage Dockerfile builds from the repository root—not `frontend/`—because `sync-changelog.mjs` must read the root `CHANGELOG.md`; the root `.dockerignore` keeps that context focused. Aspire remains intentionally uninvolved.
- **`STORYBOOK_BASE_URL` configures the Storybook link in the design-system documentation page.** The component `src/components/StoryboookLink.tsx` reads this from `siteConfig.customFields` (set in `docusaurus.config.ts` from the `STORYBOOK_BASE_URL` environment variable). In local development, it defaults to `http://localhost:9001`; in Docker builds, pass `--build-arg STORYBOOK_BASE_URL=https://cinedex.online/storybook` (or the environment's URL) to the build. `compose.yaml` already sets it to `http://localhost:9001` for local Compose runs.
