## [Unreleased]

### Added
- **`DELETE /movies-svc/auth/sessions/all`, a sign-out-everywhere endpoint** - Bearer-only, no body, no parameters, `204 No Content`, idempotent. `POST /auth/logout` ends the one session its cookie names and deliberately leaves the user's other devices signed in; this is the control that crosses that boundary, revoking every active refresh token the account owns across every family — including sessions on devices the caller no longer has. Scope comes from the subject of the validated access token and from nothing the request carries, so no input exists that could widen it past the caller. The trade in the other direction is that it cannot be narrowed either: ending one *other* session would mean exposing session identifiers to the client, which nothing does today.
  - **The caveat is part of the endpoint's contract, not a footnote.** Access tokens are stateless JWTs, so revocation cannot reach one already issued — it stays valid until its own expiry, up to `Jwt:AccessTokenMinutes` (15 by default, 5 minimum). Signing out everywhere therefore closes the ability to *obtain* new access tokens instantly while leaving a window of at most that long in which an already-stolen one still works. That gap is now written up as **SES-07** under the auth model's Known gaps, along with what closing it would cost: a per-request denylist or "issued before" watermark lookup, which is exactly the trade JWT bearer exists to avoid. The short lifetime *is* the mitigation, which is why `JwtOptions` caps `AccessTokenMinutes` at 15 rather than leaving it free. `RevokeAllSessions_CalledTwice_IsIdempotent` demonstrates the window directly — the second call is authorised by an access token whose entire session the first call revoked.
  - **Audit event `AllSessionsRevoked` (EventId 1003), emitted on every call — including the ones that revoke nothing.** Signing out everywhere is what somebody does when they believe they have been compromised, so the fact that they asked is itself the record an incident-response runbook needs, and a zero count says the panic button was pressed twice rather than that nothing happened. `Information`, not `Warning`: this is a control working, not an anomaly like 1001 (reuse detected) or 1002 (logout presenting another user's token). It carries the revoked count and nothing else — no user id, no email, no token hash — matching those two, so the log store never becomes a record of who was signed in.
  - **Routed under `auth/` rather than as a sibling `/sessions` resource**, which is load-bearing rather than cosmetic: the refresh cookie's `Path` is `/movies-svc/auth`, so a route outside it would neither receive the cookie nor be able to clear it. The endpoint clears it unconditionally, since the caller's own cookie is one of the ones it just killed.
- **The docs site and Storybook have social cards, so sharing either link renders a preview** - `static/img/og-cinedex-docs.png` (1200×630, the same shape as the SPA's `og-cinedex-light.png`) now backs `og:image` and `twitter:image`. `twitter:card: summary_large_image` already came from `theme-classic`, so `themeConfig.metadata` only has to supply what Docusaurus does not derive on its own — `og:type`, `og:site_name`, and the image's own type, dimensions and alt text, which several crawlers use to lay the card out before the image finishes downloading. `og:title`, `og:description` and `og:url` stay per page, so every documentation page shares the same card under its own heading. The SPA got its Open Graph tags in 0.10.0; the documentation site was the published surface still without one.
  - **Storybook gets one too, wired a completely different way.** `@cinedex/storybook` has no site config to hang metadata off, and **Storybook 10 removed the `managerHead` hook**, so `.storybook/manager-head.html` — already the home of the favicon — is the only injection point left. Being static HTML it cannot read the environment, so its URLs are absolute and hardcoded to `https://cinedex.online/storybook/`, the same canonical-origin choice the docs site's `url` makes. It reuses `og-cinedex-card.jpg`, the dark brand card the `staticDirs` line already serves out of `cinedex-app/public/`, so the card costs no new asset; a design-system-specific image is a drop-in replacement for two URLs. `og:title` is spelled out as "Cinedex Design System" because Storybook names its own tab **"storybook - Storybook"**, which is what a crawler would otherwise have put on the card.
  - **`url` moves off the scaffold's `cinedex.example.com` placeholder to the deployed `https://cinedex.online` origin**, which the card depends on rather than merely documents. Docusaurus resolves `image` to an **absolute** URL as `url + baseUrl + image`, and social crawlers reject a relative `og:image` — so the placeholder host would have produced tags pointing at a domain that does not exist: a preview that renders nowhere, with a green build and a passing CI. Both base paths were checked against a real build rather than reasoned about, since that is the only place the resolved value appears: `/img/og-cinedex-docs.png` locally and `/documentation/img/og-cinedex-docs.png` under the Compose base URL.

### Fixed
- **`RevokeAllActiveForUserAsync` stamped already-expired refresh tokens, keeping drained rows alive for an extra fortnight** - It was the only one of the four revocation statements missing the `ExpiresAtUtc > revokedAtUtc` filter that `RotateAsync`, `RevokeActiveFamilyAsync` and `RevokeActiveFamilyByTokenHashAsync` all carry. Stamping an expired row changes no security outcome — it is dead either way — but it moves the row out of the retention sweep's *expired, never revoked* bucket (`ExpiredRetention`, 1 day past expiry) into the *revoked* one (`ReuseDetectionWindow`, 14 days past revocation), so rows that had all but drained were kept around 13 days longer than they had earned. It also inflated the count reported by the new audit event above with tokens that were never live. The one path already using it — a password reset ending every session — gets the same correction. `RevokeAllSessions_LeavesAlreadyExpiredTokensUnrevoked` now pins the behaviour.
- **`npm run build -w @cinedex/docs-site` failed its typecheck, breaking CI's frontend job** - `StoryboookLink.tsx`, added with 0.10.0's configurable Storybook link, annotated its return as `JSX.Element`. React 19's types removed the global `JSX` namespace (it is `React.JSX` now), so the build's `tsc` step failed with `TS2503: Cannot find namespace 'JSX'` — before `docusaurus build` ever ran, which is why the site itself was fine and only the packaged build broke. It now returns `ReactNode`, the annotation `src/pages/index.tsx` already used.
- **`npm run lint` failed on the new root `vitest.config.ts`** - 0.10.0's `npm run test:ui` entry added a Vitest config at the `frontend/` root, which is the one directory with no `tsconfig` of its own; every other config file is covered by its package's `tsconfig.node.json`. ESLint's `projectService` resolves the nearest `tsconfig` per file, found none, and failed the whole lint run with `was not found by the project service` rather than skipping the file. It is now listed in `allowDefaultProject`, typescript-eslint's mechanism for exactly this — a root config file belonging to no project — which lints it against inferred compiler options. Listed file by file rather than globbed: the service rejects any entry another `tsconfig` already covers, so a catch-all would break the moment it overlapped.
- **Every docs-site link 301'd to a URL missing the `/documentation` prefix, landing on the SPA instead of the page** - Docusaurus writes `docs/features/overview/index.html` but linked to it without the trailing slash, so nginx answered each sidebar click with a 301 to the directory form. `nginx.conf` generates that redirect from the path *after* its `rewrite ^/documentation/(.*)$ /$1 break`, so the `Location` came back as `/docs/features/overview/` — prefix gone — and Caddy's catch-all handed it to `cinedex-app`. `trailingSlash: true` emits the slash up front, so the directory index resolves on the first request and no redirect is generated at all. This only reproduces against a built image: `docusaurus start` serves from `/` and never exercises the rewrite, which is why it survived to `main`.
  - **The same `nginx.conf` now serves the bundle whether or not the proxy in front kept the prefix.** Compose's Caddy passes `/documentation/` through for nginx to strip; a path-stripping proxy removes it before the container sees it, so the files have to resolve from the root as well. A second `location /` covers that shape. The old `location = / { return 308 /documentation/; }` is gone with it — behind a stripping proxy it targeted a path the proxy strips straight back to `/`, an infinite redirect loop. Assets keep resolving in both shapes because `baseUrl` is baked into the built HTML, so even a root-served page requests `/documentation/assets/…`.
- **The docs site's Storybook link pointed at a URL that renders a blank page** - `STORYBOOK_BASE_URL` defaulted to `https://cinedex.online/storybook`, without the trailing slash. Storybook's built `index.html` references its assets **relatively** (`./sb-manager/runtime.js`), so a browser at the un-slashed URL resolves them against `/` and requests `https://cinedex.online/sb-manager/runtime.js` — which the SPA's catch-all route answers with **HTML at status 200**. The browser then executes HTML as JavaScript: Storybook renders blank, and no console message names the cause. The default now carries the slash, as do the deployment examples in `docs/frontend/documentation-site-setup.md`. `StoryboookLink` uses the value verbatim as an `href` and never appends to it, so the slash cannot double up, and the local `http://localhost:9001` default needs none — browsers normalise a path-less URL to `/` on their own.
- **Both docs-site admonitions rendered as literal `:::info` text instead of callout boxes** - `docs/features/overview.md` and `docs/security/overview.md` opened theirs with Docusaurus 2's space-separated title syntax (`:::info Adapted from the repository's READMEs`). Docusaurus 3 moved to MDX v3, where a custom title must be bracketed (`:::info[…]`); the space form no longer parses as an admonition and falls through to the page as plain text. Both were live on the deployed site with the `:::` markers visible. Like the Mermaid wiring documented next to them, this is a **silent** failure — MDX raises nothing, the build stays green, and only the rendered page shows it. Both now use the bracket form and render as real callouts.

## [0.10.0] - August 15 2026 Frontend Motion, Tokens & Session Security

### Added
- **A `--danger` status ramp, and the error surface now uses it** - `tokens.css` gains `--danger`/`--danger-bg`/`--danger-border` (`#a83630` light, `#e8796e` dark) alongside the existing warning and success ramps, with a matching line in `theme.css`'s bridge. The three places that render a *rejected field* — `Label`'s `tone="error"`, `Field`'s error message, and `Input`'s `invalid` variant — were all painted with the **warning** ramp for want of anything better; they move to `--danger`. The genuine warnings keep theirs: the lockout `Alert`, `StatPair`'s warning tone and `AuthCard`'s warning kicker are all still amber, which is the distinction the new token exists to make. **This is the one visible behaviour change in this entry** — an invalid email now reads red rather than amber.
- **`--border-strong`, a second border weight for control edges** - `--border` (`#e5e4e8` / `#34313a`) stays the decorative hairline at 1.27:1 and continues to draw card edges, separators, the `StatPair` grid and `InlineActionRow`'s top rule. The new `--border-strong` (`#93909a` / `#57535f`, 3.14:1) draws anything the user has to find and click into: `Input`, `OtpInput`'s cells, `Checkbox`'s box and `Button`'s outline variant. One token could not serve both — the hairline reads as elegant on a bright monitor and as "where do I type" on a dim laptop.
- **"Rack focus", a camera-language transition between auth screens (`ScreenTransition`)** - Moving between auth screens was a single-frame swap: nothing in the motion said whether you had advanced, gone back, or failed. The outgoing screen now defocuses and recedes while the incoming one arrives out of focus and resolves — 520ms out, 640ms in delayed by 180ms, 820ms door to door with a 340ms overlap where both are blurred and neither is readable. Five variants encode what the copy cannot: `forward` and `back` differ only in which screen grows, `lockout` drops scale entirely so a failed sign-in does not read as progress, `accountReady` holds a 200ms beat before moving, and `coldLoad` has no outgoing half. `prefers-reduced-motion` collapses all five to one 200ms opacity cross-fade. The easing is the design's exact `cubic-bezier`, solved by a small Newton-Raphson helper rather than mapped onto GSAP's `powerN` names — `Brand/timelines.ts` already documents what that mapping costs.
  - **The outgoing screen is a clone of its own DOM, not a React subtree kept alive.** Keeping the subtree mounted is the obvious approach and it does not work: whatever renders the screens — a router `Outlet`, a step-switching screen — re-renders the "outgoing" copy against the new state, so the screen cross-fades with itself. The clone is frozen by construction. It is taken imperatively through `useCaptureOutgoing`, because React commits DOM before layout effects run, so the event that *causes* the change is the last moment the outgoing markup still exists. With no capture the move degrades to `coldLoad` rather than breaking, which is also what keeps every screen storyable with no provider — the same shape as `useLinkComponent`.
  - **Two of the flow's edges are not navigations at all.** `ForgotPasswordScreen`'s request/sent step is `useState` inside one component, and it is the only forward *and* backward pair a user can reach by clicking today; the lockout is a search param, not a path. So the host keys on an opaque string rather than on the router, and the screen carries its own alongside the router's. Nested hosts capture at every level and only the one whose key actually changed mounts its snapshot — otherwise the level that did not move pins a full-screen freeze-frame over the live UI.
  - **The 340ms overlap puts two `<h1>`s on the page**, so the snapshot is `inert` and `aria-hidden`, and focus moves to the incoming heading on completion rather than at the start — pointing a screen reader at a heading that is still blurred out helps nobody. A cold load never takes focus.
  - **The whole 820ms sequence is unit-tested rather than eyeballed**, by scrubbing a paused GSAP timeline with `progress()` — the approach `Brand/timelines.test.ts` established. The spec's variant table is the fixture, so the design document is executable. Three further tests assert the thing scrubbing structurally cannot: that the timeline actually *plays*, including under `StrictMode`'s double-invoked effect. `Solution/AuthTransitions` in Storybook is the review surface, and covers the three variants no route reaches. The design's "Verify your email" and "Account ready" screens appear there as labelled placeholders — their copy is still an unreviewed draft, so it is deliberately not shipped as a component.
- **The brand lockup scales (`Brand`, `BrandApertureAnimation` and `BrandFocusRingsAnimation` take a `size`)** - All three variants rendered at exactly one size, which is why the docs site's hero had to sit a 20px mark next to a page title. `brandSize.ts` adds a five-step named scale — `XS` through `XL`, with `M` the new default and `XS` preserving the size everything rendered at before — resolved to classes for the mark and the wordmark *together*, so the two halves cannot drift apart. A positive whole number is also accepted: 1–5 alias the named steps and higher numbers continue the scale past `XL`. Zero, negatives, fractions, `NaN` and infinities throw a `RangeError` rather than rendering something arbitrary. The text half moves into its own `Wordmark` component so the sizing has one home, and `BrandSize` plus all three prop types are now exported.
- **`npm run test:ui`, one Vitest UI across the whole frontend workspace** - A new root `vitest.config.ts` declares the four testable workspaces — `cinedex-app`, `atoms`, `compounds` and `solution` — as Vitest projects, so a single UI with coverage enabled covers every suite instead of needing one process per package.

### Changed
- **The palette is retuned around chroma and lightness discipline ("Amethyst, disciplined")** - The accent drops from `#aa3bff` to `#6d41a9` in light and `#c084fc` to `#bc98f9` in dark: the same violet hue at roughly half the OKLCH chroma (0.269 → 0.160). At the old value the brand out-saturated its own warning ramp 2.4 to 1 and read as the loudest thing on every screen; it also missed WCAG AA against white at 4.39:1, which the new value clears at 7.05:1 as a side effect rather than as a separate fix. `--accent-bg` and `--accent-border` now derive from a lighter, more chromatic sibling (`#8e57d8`) rather than from the foreground, because a 10% wash of a foreground that dark comes out muddy grey — the same foreground/tint-base split `--warning` and `--success` already used.
  - **Dark-mode neutrals move off Tailwind's default greys onto the accent's own hue.** `--text`, `--text-h`, `--bg`, `--border` and `--code-bg` were `gray-400`, `gray-100` and friends, which sit at OKLCH hue ≈ 261 (blue) while light mode's hand-authored neutrals sit at ≈ 300 (violet). Dark mode consequently lost the violet cast that makes light mode feel composed. All five now carry it in both themes.
  - **The four status foregrounds share a lightness.** `--accent`, `--danger`, `--warning` and `--success` sit near OKLCH L 0.48–0.50 in light and L 0.70–0.76 in dark so they read as siblings rather than a soloist and a backing group; `--warning` and `--success` shift slightly to join that set. `tokens.css` states both this and the chroma ceiling as rules, since neither survives being adjusted by eye.
- **The docs site needed no change**, which is the design working: `custom.css` already points Infima's seven primary shades at `var(--accent)` and `color-mix`es the rest, so the whole site followed the new accent on its own.
- **Both brand intro sequences are GSAP timelines, replacing a hand-rolled rAF animator** - `Brand/animations.ts` (a `lerp(a, b, eOut(t))` loop plus `useMarkAnimation`/`useDelayedReveal`) becomes `Brand/timelines.ts` and a single `useMarkTimeline`, matching the "pure builder returning a paused timeline" shape the package now follows throughout. Every tween writes SVG **attributes** through `attr:` rather than GSAP's `rotation`/`scale`/`x` shorthands, which is what preserves the mark's verified geometry: the shorthands route through CSS `transform` with a `transform-origin` resolved off `getBBox()`, a different coordinate model from the `rotate(deg cx cy)` strings `mark.ts` was validated against. Measured end to end against the old implementation, the worst divergence is 5e-5 — entirely GSAP's 4-decimal attribute rounding. It also keeps `opacity` on the attribute instead of leaving a stale one beneath `style.opacity`, and it runs in jsdom, which implements neither `requestAnimationFrame` nor `getBBox` — so `timelines.test.ts` can scrub both 1.2s sequences frame by frame rather than only asserting the settled state. `prefers-reduced-motion` scrubs to `progress(1)`, making the reduced-motion render and the settled render the same DOM by construction rather than by two code paths agreeing. `@cinedex/solution` takes `gsap` as a dependency; static `Brand` pulls in none of it.
  - **One footgun is pinned in a comment rather than left to be rediscovered**: GSAP's `powerN` naming is off by one from the usual quadratic/cubic vocabulary, so `power2` is the cubic these curves were designed against. `power3` is quartic, overshoots by up to 0.11 across the first half of every beat, and reads as the mark snapping open early.
- **The docs site resolves Infima through `@cinedex/theme`'s tokens** - `custom.css` pointed Docusaurus's `--ifm-*` variables at a hand-transcribed HSL copy of the brand accent that had already gone stale — its own comment referenced a package path that no longer existed. Infima's seven primary shades now derive from `var(--accent)` via `color-mix`, and surface, ink and border follow the same tokens the SPA and Storybook use, so the accent has exactly one definition and a rebrand stays a one-line change. The homepage drops its redundant eyebrow and `<h1>` — the lockup already says the product name — and renders the mark at the new scale; the site also gains a Cinedex favicon and two documentation pages covering frontend architecture and the design system.
- **The refresh-token cookie's `Secure` attribute is configurable, still defaulting to on** - `RefreshTokenCookie` was `static` with `Secure = true` compiled in and a `__Secure-`-prefixed name — correct for every deployed environment and unusable over plain HTTP, which is what the Aspire local-dev workflow now serves the SPA on since Vite terminates no TLS there. It becomes a DI singleton reading `Authentication:RefreshTokenCookie:Secure` (default `true`, stated explicitly in `appsettings.json`), and the cookie **name** flips with the attribute: `__Secure-cinedex_refresh_token` when secure, plain `cinedex_refresh_token` when not, because the `__Secure-` prefix is only legal alongside the attribute it names. Compose and production are unaffected — both stay on HTTPS.
  - **The web service also gained a frontend CORS policy and static-file serving.** The policy binds to a configured origin and is only added to the pipeline when one is actually set; `UseStaticFiles` publishes the Open Graph card assets now under `wwwroot`. The Aspire AppHost's UI endpoint moves from HTTPS to HTTP to match, and passes `Frontend:BaseUrl` through to the web service so password-reset links resolve to the right origin.
- **The docs site's Storybook link is configurable per environment** - The design-system page hardcoded `http://localhost:9001`, which is wrong in every deployed environment. A `STORYBOOK_BASE_URL` build argument now flows through `docusaurus.config.ts`'s `customFields` into a small link component: unset, it defaults to `http://localhost:9001` for local development; the Dockerfile defaults to `https://cinedex.online/storybook`; and Compose passes the local URL explicitly. It resolves at build time, so there is no runtime config file and no markdown to regenerate.

### Removed
- **`JwtBearerOptions.MapInboundClaims = false`, and the duplicate user-id claim that made it look necessary** - The access token wrote the user id twice, once as the RFC 7519 `sub` and again as `ClaimTypes.NameIdentifier`, and reading the first of those had meant switching off inbound claim mapping for **every** request the API authenticates — a global change in service of one endpoint. Nothing broke, because the token spells its role and name claims in long form already and nothing reads `ClaimTypes.Email`; but the next caller to reach for `ClaimTypes.Email` would have got a silent `null` and a green build. The token now carries the subject once, mapping is back at its default, and presentation reads the caller through the new `ClaimsPrincipalExtensions.TryGetUserId`, which accepts either spelling so no endpoint's identity depends on that switch again. `Login_AccessTokenCarriesTheUserIdExactlyOnce` pins the single claim.

### Fixed
- **The "Forgot?" link rendered at 16px next to its own 10px label** - `AuthLink`'s shared class carried no `--type-*` step, so the link fell through to `base.css`'s `:root` font (18px, 16px under 1024px). The bug was invisible wherever a parent already set a step — "Create one" sits inside `InlineActionRow`'s `text-caption` and looked correct — but "Forgot?" sits in `Field`'s label row, which sets none. It now states `text-caption` itself, so the link is self-sufficient rather than dependent on where it happens to be mounted.
- **The SPA is spelled `cinedex-app`** - `frontend/apps/cinadex-app/` is now `frontend/apps/cinedex-app/` and the workspace package is renamed to match, so the folder, the package name and the product finally agree. The misspelling had been documented as deliberate (in `docs/README.md`, `frontend/CLAUDE.md` and the app's own `CLAUDE.md`); those notes are gone with it. Every reference follows: the `-w cinedex-app` script targets and `workspaces` entry, `apps/cinedex-app/Dockerfile` and the manifest `COPY` lines in the Storybook and docs-site images, the Compose service/image/container name and the `depends_on` behind `cinedex-edge`, Caddy's `reverse_proxy` upstream, `AppHostConstants.FrontendAppDirectory`, the ESLint route override and Prettier ignore, `@cinedex/storybook`'s `staticDirs`, the CI coverage-summary step, and `.claude/launch.json`. The lockfile records the new workspace path — `npm ci` from `frontend/` is enough to pick it up.

- **Spelling: `Cinadex` → `Cinedex` across the repo** - The static landing and changelog pages the web service serves (`index.html`, `changelog.html`) rendered the brand in the navbar as "Cinadex", as did the deployment tables in `backend/README.md` and `docs/getting-started.md` and the Compose topology diagram in the docs site. Also fixes a misspelled `configuation` local in `Cinedex.Persistence.Postgres`'s `AddPersistenceAdapter`.

### Security
- **`POST /auth/logout` now ends the session it was asked to end, and only if the caller owns it** - Two independent defects, both in the one statement logout used to run (`RevokeByTokenHashAsync`, revoke the row matching this hash). It ignored who was asking, so a browser holding one user's refresh cookie alongside another user's bearer token signed out the wrong person; and it revoked one *row* where a session is a *family*, so a rotation that landed moments before the logout — a second tab refreshing, say — kept a live successor and the session outlived the logout that closed it. `ITokenService.RevokeRefreshTokenAsync` is replaced by `RevokeSessionAsync(ownerId, refreshToken, …)`, backed by `IRefreshTokenRepository.RevokeActiveFamilyByTokenHashAsync`, which resolves the family through a subquery and revokes every active token in it — in one statement whose `WHERE` carries the ownership test.
  - **The ownership test is a condition of the write, not a question asked before it.** The alternative — read the token's owner, compare, then revoke — is two round trips with a window between them in which a rotation can change the answer, and it needs a port method that hands back a token's owner, which is an existence oracle for a secret the rest of this interface is careful never to confirm. The subquery form has neither problem and matches how `RotateAsync`, `RevokeActiveFamilyAsync` and the retention sweep were already written.
  - **Revoking the family stays bounded.** Each login starts its own family, so signing out of one session leaves the user's other logins alone — pinned by `Logout_LeavesTheSameUsersOtherSessionsAlone`, alongside `Logout_WithRotatedToken_AlsoRevokesTheSuccessor` for the gap this closes and the existing cross-user test for the other.
  - **The response is unchanged at `204` on every path**, so none of this is observable from outside: revoked, refused and unknown are indistinguishable to a caller, and the cookie is still cleared unconditionally because logout is idempotent. What changed is the inside — a refresh token that exists and belongs to somebody else now logs `RefreshTokenOwnershipMismatch` at **warning**, the level the same evidence already gets in `RefreshTokenReuseDetected`, rather than passing as information. Unknown and already-revoked tokens are ordinary and log nothing at all. The message carries no identifiers, keeping to this subsystem's rule that the log store must not become a record of who was signed in.
  - **Worth being straight about the size of the hole**: anyone holding another user's refresh token could already exchange it at `/auth/refresh` for tokens in that user's name, which is strictly worse than ending it. The ownership condition is correctness for the shared-browser case and defence in depth for the rest — not a closed privilege escalation.

## [0.9.0] - August 8 2026 Frontend Workspace, Component Tiers & Docs Site

### Added
- **The Docusaurus docs site now has a production-style Docker image and Compose service** - `frontend/apps/docs-site/Dockerfile` builds the static site with Node and serves only the resulting bundle from Nginx. Caddy publishes it under the stack's existing HTTPS origin at `https://localhost:9000/documentation/`, while port 9004 remains a direct diagnostic path. Its build context is the repository root because the changelog page is generated from the root `CHANGELOG.md`; a root `.dockerignore` excludes the backend, local tooling and build output so that requirement does not turn every docs build into a whole-repository upload.
- **Auth screens for `cinedex-app` (sign in, two-factor code, create account, forgot/reset password, signed out)** - The SPA's first real routes: `@tanstack/react-router`, file-based under `src/routes/`, now drives a `RouterProvider` in `main.tsx` in place of a bare `<App/>`. Seven screens across six routes (`/login`, `/login/verify`, `/register`, `/forgot-password`, `/reset-password`, `/signed-out`) render the auth flow the "Cinedex auth screens" design canvas specified, in both light and dark. This pass is UI-only — local component state and stubbed submit handlers, no `fetch` calls to the backend's `/movies-svc/auth/*` endpoints — leaving full wiring to the "Lane E: Frontend Runtime" work the auth execution plan already tracks separately.
  - **Tailwind CSS is new, and scoped to `cinedex-app` alone.** `@cinedex/components` stays CSS-Modules-only by its own convention, so the new `src/styles/tailwind.css` maps Tailwind's theme onto the library's existing `light-dark()` tokens via `@theme inline` (`bg-bg`, `text-accent`, `rounded-sm`, etc. all resolve through `tokens.css`) rather than duplicating colours or introducing a second design system — the design's own "board language" mockups turned out to already match the library's ink/purple tokens closely.

- **The docs site is now built from `@cinedex/theme` and the component tiers rather than styled to look like them** - `@cinedex/docs-site` takes `@cinedex/theme`, `@cinedex/atoms` and `@cinedex/solution` as real dependencies, the same way the SPA does. `src/css/custom.css` points Infima's own `--ifm-*` variables at the tokens — accent, surface, ink, hairlines, fonts, code background — instead of restyling Docusaurus, and the homepage renders the actual `Brand`, `Button`, `Card` and `Separator`; both of its CSS Modules are deleted. Only consumers that switch theme at runtime are affected; a page that merely loads under a theme resolves everything.

## [0.8.0] - August 4 2026 Persistence Ports & the FoundryOceanus Split

### Added
- **Persistence abstraction libraries (`NuGetLibraries/FoundryOceanus.Persistence.*`)** - Three packable libraries that put a unit of work, real transactions and repository resolution in front of Entity Framework, so the application layer can be written without a reference to it. Nothing in `src/` consumes them yet; this ships the libraries, their documentation and their tests, and leaves migrating the existing adapters as separate work with its own review.
  - **The split is the whole point.** `FoundryOceanus.Persistence.Abstractions` holds the ports — `IUnitOfWork`, `ITransaction`, `ISavepoint`, `IRepository`, the exception hierarchy — and has **no `PackageReference` entries at all**, which is the only way the "application code must not depend on infrastructure" rule survives contact with a deadline. `FoundryOceanus.Persistence.EntityFrameworkCore` implements them against `Microsoft.EntityFrameworkCore.Relational`, and `FoundryOceanus.Persistence.EntityFrameworkCore.Postgres` adds the Npgsql-specific half on top of `Npgsql` alone — not the EF provider package, which would have pinned a provider version for consumers that already choose their own.
  - **`IUnitOfWork` exposes six members where `DbContext` exposes around forty.** No `IQueryable`, no `DbSet`, no `ChangeTracker`, no raw-SQL escape hatch: a composable query handed to a command handler is the ORM with extra steps, and code that genuinely needs raw SQL belongs in an adapter where it can depend on the provider honestly. There is deliberately no `IRepository<TEntity>` with `GetAll`/`Add`/`Update`/`Delete` either — a generic CRUD repository is the same unconstrained surface under a different name. `IRepository` is a bare marker that constrains what `Repository<T>()` will resolve; the interfaces deriving from it are meant to be named for the domain (`IRefreshTokenRepository.RotateAsync`), not for the database.
  - **One `DbContext` per scope, shared between the unit of work and every repository it hands out** — the invariant that makes a single `SaveChangesAsync` flush all their writes and a single transaction cover all their statements. It is checked rather than trusted: repositories deriving from `EfRepository<TContext>` implement `IDbContextBound`, and resolving one bound to a different context throws instead of letting its writes commit on a second connection outside the caller's transaction, which is what an injected `IDbContextFactory` silently does today. Registering the context as `Singleton` or `Transient` is rejected at startup for the same reason.
  - **`TransactionIsolationLevel` has four values, not `System.Data.IsolationLevel`'s seven.** `ReadUncommitted`, `Snapshot` and `Chaos` are fictions on PostgreSQL — the first is silently treated as `ReadCommitted` — and offering levels the database will quietly reinterpret is how an abstraction starts lying to the people reading it. Transactions do not nest, because databases do not: `BeginTransactionAsync` throws rather than returning a handle whose rollback would do nothing, and `CreateSavepointAsync` covers partial rollback. Disposing an uncommitted transaction rolls it back; `RollbackAsync` tolerates being called on a completed transaction while `CommitAsync` does not, so a rollback in a `catch` block cannot throw over the exception that sent it there.
  - **Provider errors are classified once, in one file.** `NpgsqlExceptionTranslator` maps SQLSTATE to `DuplicateKeyException`, `ReferentialIntegrityException`, `ConcurrencyConflictException` and `TransientPersistenceException`, and claims everything it cannot name as `UnclassifiedPersistenceException` rather than letting an `NpgsqlException` reach code written not to know PostgreSQL exists. Translator order is load-bearing — the EF translator's catch-all would otherwise claim every `DbUpdateException` before any SQLSTATE was read — so it is not left to the composition root: `CompositePersistenceExceptionTranslator` sorts that catch-all last however the registration calls were ordered, while everything else keeps the order it was registered in. `57014` is deliberately *not* transient — it is nearly always `statement_timeout`, and retrying a too-slow query is how a slow endpoint becomes a busy one. The SQLSTATE constants come from Npgsql's own `PostgresErrorCodes`, which already has all 238; a private copy would have been a second list to keep in step with PostgreSQL for no benefit.
  - **`ExecuteInTransactionAsync` retries only on `IsTransient`,** with exponential backoff and jitter — two transactions that collided and retry after the same fixed delay just schedule the same collision again. It calls `DiscardChanges()` between attempts, because a rollback undoes the database's work but leaves the failed attempt's entities tracked against a snapshot that no longer exists. The requirement that the operation be safe to run twice is documented on the method rather than assumed.
  - **Advisory locks hang off `DbContext`, not `IUnitOfWork`,** and only in the PostgreSQL package. An advisory lock is a database mechanism, not a business concept; needing a `DbContext` to call one is what keeps it in the adapter where it belongs. All are transaction-scoped (`pg_advisory_xact_lock`) — session-scoped locks are not offered, because with connection pooling one that is not explicitly released stays held on a pooled connection and is eventually handed to an unrelated request. Text keys are hashed by `hashtextextended` **in PostgreSQL**: `string.GetHashCode()` is randomised per process on .NET Core, so hashing in .NET would give each instance of a service a different lock for the same key — invisible on one machine, and broken the moment it scales out.
  - **`IUnitOfWorkScopeFactory` gives background services a per-iteration scope** without injecting `IServiceScopeFactory`, which works but puts the container back in front of code that had stopped knowing about it.
  - **Registration mistakes fail at startup rather than quietly.** Two contexts asking for the same `WithKey(...)` value throws instead of letting `TryAddKeyedScoped` drop the second — every consumer of that key would otherwise resolve the first context and write to the wrong schema. Re-stating a claim your own context already holds is explicitly not a conflict, so the documented "composition split across modules" pattern works: one module contributing repositories and another calling `AsDefault()` for the same context no longer throws about a context that does not exist.
  - Tested in a new `tests/FoundryOceanus.Persistence.Tests`: 39 tests that need no database (SQLSTATE mapping, translator ordering under every registration order, registration/lifetime/key validation, the retry loop against a recording fake) plus 25 integration tests on a `postgres:17-alpine` Testcontainer for the things a fake cannot honestly stand in for — real 23505 translation, savepoint rollback, advisory-lock contention, and a genuine write-skew serialization failure at `Serializable`.

The scheduler worker now sweeps them every ten minutes in bounded batches.
  - **Two retention windows, because the two kinds of dead row are dead for different reasons.** An expired-but-never-revoked row is unreachable by every code path and is deleted a day past expiry. A revoked row is the only thing that makes replaying an already-rotated token distinguishable from presenting an unknown one, so it is kept for fourteen days past revocation — well beyond the seven-day token lifetime — preserving the trigger consumed by the family-wide reuse response. Neither predicate can match a live session's tail, which is unrevoked and unexpired.
  - **Bounded so it cannot block issuance or rotation.** Each batch is a single `ExecuteDelete` in its own implicit transaction, so row locks are held for one statement rather than across a sweep, and a run stops at `BatchSize × MaxBatchesPerRun` rows — a backlog drains over successive sweeps instead of becoming one long-running delete. Interval, batch size and both windows are validated at startup via `ValidateOnStart`.
  - A new composite index `IX_refreshTokens_revokedAtUtc_expiresAtUtc` serves both sweeps and supplies each its ordering.   - `RevokeRefreshTokenAsync` (logout) became a single conditional `UPDATE` filtered on `revokedAtUtc IS NULL` instead of a read followed by a tracked save. Still idempotent and one round trip shorter, and an earlier revocation's timestamp now survives a concurrent logout rather than being overwritten by the later one.
- **Branded password-reset email** - The reset email is now a designed HTML message in the Cinedex crimson palette, with an embedded logo, a call-to-action button, and the one-hour expiry stated inline, replacing the previous single-sentence body. `HtmlEmailBody` gained an `InlineImages` collection and `SmtpEmailSender` maps it to MIME linked resources, so the logo travels with the message and needs no remote fetch — a remote image would have told a web server which recipients opened a reset email. Composition stays in the application layer via a new `CinedexEmailLayout`; the SMTP adapter still only delivers. Design recorded in [the spec](docs/superpowers/specs/2026-07-26-branded-password-reset-email-design.md).

### Fixed
- **`/health/ready` now probes the database the application actually connects to** - The Postgres readiness check read `ConnectionStrings:DefaultConnection` eagerly from `builder.Configuration`, capturing whatever happened to be configured at that point in startup rather than the value the `DbContext`s are handed once the host finishes building. It now resolves the connection string lazily from the built `IServiceProvider`, the same way `AddAuthenticationPersistence` does; the eager read is kept solely as a startup guard that fails fast when the key is missing altogether. A readiness probe reporting on a different database than the one serving requests is worse than no probe at all — under `WebApplicationFactory` it captured `appsettings.json`'s `<SECRETS>` placeholder and returned 503, while on a developer machine User Secrets quietly made it green by pointing it at a local Postgres that was not the database under test.

### Security
- **Refresh-token reuse revokes the compromised family** - Presenting a known, unexpired refresh token that already has a replacement link now revokes every active token in that login family atomically before returning the same generic `401` and clearing the cookie. A PostgreSQL transaction-scoped advisory lock serializes rotations and reuse responses within the family, so a replacement inserted by a concurrent refresh cannot survive. Warning event `1001 / RefreshTokenReuseDetected` records only the number of tokens revoked — no token material, family or user identifiers, email, or username. Unknown, expired, logged-out, and already-family-revoked tokens retain the ordinary invalid-refresh policy; other login families and existing access tokens are unaffected. Documented in the [Auth & Security Model](docs/auth-security-model.md).
- **Refresh tokens now carry a family identifier** - Every persisted refresh token has a new indexed `familyId`: `POST /auth/login` mints a fresh one per session and each rotation through `POST /auth/refresh` copies the incoming token's value onto its replacement, so an entire rotation chain is reachable by one indexed lookup instead of by walking `ReplacedByTokenHash` hash by hash. The reuse response above consumes that identifier to contain a compromised session without touching the user's other login families. Because rows written before the column existed belong to no real family, the migration deletes every stored refresh token rather than inventing one — sessions that were live when it ran end and clients log in again, which also keeps the migration unable to fail against a populated database and block the Compose migrator. Documented in the [Auth & Security Model](docs/auth-security-model.md).
- **Password reset links now expire after one hour** - `AddAuthenticationAdapter` sets `DataProtectionTokenProviderOptions.TokenLifespan` explicitly, replacing Identity's one-day default and narrowing the window in which an intercepted or forwarded reset link stays usable. The lifespan applies to every token issued by Identity's `Default` provider, which today means password reset only. Documented in the [Auth & Security Model](docs/auth-security-model.md).

## Version Numbering Strategy

This project follows [Semantic Versioning](https://semver.org/) with the following scheme for pre-1.0 development:

- **PATCH** (0.x.y) - Bug fixes, testing infrastructure, tooling improvements, code quality
- **MINOR** (0.x.0) - New features or significant capability additions
- **MAJOR** (1.0+) - Reserved for production-ready release with breaking changes
