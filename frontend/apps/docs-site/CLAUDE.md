# @cinedex/docs-site

A Cinedex-branded [Docusaurus](https://docusaurus.io/) 3 site (classic template, TypeScript), scaffolded with `npx create-docusaurus@latest docs-site classic --typescript`.

One of three apps in the `frontend/` npm workspace — see [`../../CLAUDE.md`](../../CLAUDE.md).

## Commands (from `frontend/`, the workspace root)

```bash
npm run docs-site                       # http://localhost:9004
npm run build -w @cinedex/docs-site      # static build to build/
```

Both delegate to this package with `-w @cinedex/docs-site`.

## Layout

```
docusaurus.config.ts     # branding, navbar/footer, blog disabled (blog: false)
scripts/sync-changelog.mjs  # generates src/pages/changelog.md, see Notes
src/css/custom.css       # Infima color scale, see Notes
src/global.d.ts          # /// <reference> for Docusaurus's ambient module types
docs/features/           # product/architecture docs, adapted from README.md + backend/frontend READMEs
docs/security/           # auth/authz docs, adapted from docs/auth-security-model.md + the auth design specs
static/img/               # favicon.svg (copied from cinadex-app) — the only static asset here
```

## Notes

- **`/changelog` is generated, not written.** `scripts/sync-changelog.mjs` copies the root `CHANGELOG.md` into `src/pages/changelog.md` (git-ignored, see `frontend/.gitignore`) before every `start`/`build`, chained with `&&` — the same pattern `cinadex-app`'s `"build": "tsc -b && vite build"` already uses, not npm `pre`/`post` hooks. It also rewrites repo-relative markdown links (`docs/auth-security-model.md`, etc.) to absolute `github.com/felipedferreira/Cinedex/blob/main/...` URLs, since this site only hosts a handful of pages, not the whole repo — `onBrokenLinks: 'throw'` in `docusaurus.config.ts` would otherwise fail the build on every such link. **Edit only the root `CHANGELOG.md`** — never `src/pages/changelog.md` directly, it will be overwritten. This is a different mechanism from `backend/CHANGELOG.md`'s sync (a committed, CI-verified copy the web service serves) — same source file, two unrelated consumers.
- **`start` runs the dev server and a changelog file-watcher concurrently** (via the `concurrently` devDependency): one shot of the sync script first (so `src/pages/changelog.md` exists before Docusaurus's initial content scan), then `docusaurus start --port 9004` alongside `sync-changelog.mjs --watch`, which re-syncs on every change to the root `CHANGELOG.md` so the page hot-reloads.
- **This package keeps Docusaurus's own generated `tsconfig.json`** (`extends: "@docusaurus/tsconfig"`) rather than the `tsconfig.json` + `tsconfig.*.json` split `cinadex-app`, `@cinedex/storybook` and the `@cinedex/*` libraries use. That split exists because Vite's build reads tsconfig for module resolution and needs a separate node-context config for `vite.config.ts`; Docusaurus's own bundler doesn't read tsconfig for compilation at all — the file exists only for editor support and the `typecheck` script (`tsc`, no-emit). `projectService: true` in the root ESLint config still resolves this single file as the nearest tsconfig, same as every other package.
- **Infima's primary-color scale (`src/css/custom.css`) is derived from `@cinedex/theme/tokens.css`'s `--accent: light-dark(#aa3bff, #c084fc)`** — the same purple the SPA and Storybook use. Each of Infima's required 7 shades is the base hue/saturation with lightness shifted by fixed steps, expressed as `hsl(...)`. If the brand accent ever changes, regenerate with Docusaurus's own color-generator tool (linked from "Styling your site with Infima" in the Docusaurus docs) rather than hand-tweaking the shifted values.
- **`docs/` holds two hand-authored categories, not an autogenerated dump of the repo's markdown.** `docs/features/` and `docs/security/` are curated, one-time adaptations of the repo's own docs (root `README.md`, `backend/README.md`, the frontend package READMEs, `docs/auth-security-model.md`, and the two auth design specs under `docs/superpowers/specs/`) — not a live sync like `/changelog`. That's deliberate: those source docs vary too much in voice and intended audience (some are publication-quality prose, others are dense internal/library-engineer material) for a mechanical copy to work. **This means the site can drift from the source docs over time** — there's no automated re-sync, so a change to `docs/auth-security-model.md` or a backend README doesn't propagate here automatically. `_category_.json` in each folder sets the sidebar label/position; `sidebars.ts`'s single `docsSidebar` autogenerates the rest from folder structure and each page's `sidebar_position` front matter.
- **`docs/security/how-this-was-built.md` is missing a live issue list on purpose.** It's adapted from `docs/superpowers/plans/2026-07-29-auth-execution-plan.md` (a Linear-project-coupled execution plan) and the two design specs, but ships without a live Linear issue list — the Linear MCP connector wasn't authorized when this content was written. Extend it once that connector is available, rather than hand-copying issue data that can't be kept current.
- **Every diagram is a ```mermaid fence — there is no ASCII box art in `docs/`, deliberately.** This needs _two_ things wired in `docusaurus.config.ts`: `markdown: { mermaid: true }` and `'@docusaurus/theme-mermaid'` in `themes`. **Docusaurus does not error on a fence language it doesn't recognise** — it renders it as a plain code block. So removing either one turns every diagram back into raw `flowchart TD ...` text _with a green build and a passing CI_; this exact failure shipped once already. `themeConfig.mermaid` maps the light/dark Mermaid themes, which is load-bearing because `colorMode.respectPrefersColorScheme` is on. `scripts/check-diagrams.mjs` runs as part of `build` and fails it if either half of that wiring goes missing. It checks **only** the wiring — the content rules (no ASCII box art, no `;` inside a `sequenceDiagram`) are repo-wide and owned by `scripts/check-diagrams.mjs` **at the repository root**, which CI runs as its own step; they are not duplicated here, so a violation is reported once. Both are **static** checks: Mermaid renders client-side, so neither can catch every syntax error. Verifying a diagram change means **looking at the rendered page**.
- **Search is a local, build-time index** (`@easyops-cn/docusaurus-search-local`), not Algolia — no account, no application, no network call from the rendered page. `hashed: true` cache-busts the index filename per build. It only produces an index during `docusaurus build`; **`docusaurus start` has no search box**, which is expected, not a regression.
- **`@docusaurus/faster`'s dependency tree needed two `allowScripts` entries** in the root `frontend/package.json` (`core-js: false`, `@swc/core: false`) to get past `.npmrc`'s `strict-allow-scripts` — see `../../CLAUDE.md` for why both are safe to skip. Neither `@docusaurus/theme-mermaid`/`mermaid` nor the search plugin added any new install script, so no further entries were needed.
- **No Docker/Compose/Aspire integration yet** — local dev only. `npm run lint`, `npm run format:check` and `npm run build` from `frontend/` already exercise this package automatically (they fan out across every workspace member), so it's covered by the existing CI job with no workflow file changes.
